# WebGPU 园区：程序化写实视觉方案

2026-10-19，独立视觉研究；本轮未修改应用代码。目标是保留现代园区与代码生成资产，让尺度、构造、材质、光照和运动在观察中可信。这里的“仿真”是视觉物理可信，不是建筑结构验算、照度认证或植物生长科学模型。无需 Blender、外部模型、照片纹理或外部 HDRI；真实建筑照片仅用于设计对照。

**已有基础与画面证据**

当前 [layout.js](../../src/campus/layout.js) 已定义米制七栋建筑、两庭院；[buildings.js](../../src/campus/buildings.js) 已有近景真实倒角、窗洞厚度、框料和胶缝。[building-materials.js](../../src/campus/building-materials.js) 按米定义颗粒频率和浮雕，并按像素足迹过滤；[whole-tree.js](../../src/campus/whole-tree.js) 保留父子枝系，[vegetation.js](../../src/campus/vegetation.js) 已有叶卡 mip 覆盖率处理和空间分批。这些规则值得继承，GLSL 注入实现另行迁移。

已直接查看无加载遮罩的 [林下镜头](../../out/campus/shot-4.png)、[远望镜头](../../out/campus/shot-6.png)、[廊下历史图](../../out/campus/tree-light-combined-43.png)，并确认 `/tmp/golden-temple-audit-campus.png` 为门廊画面。我的视觉判断：空间与构造已成立，但多栋外墙和屋顶在远望中显得同质；玻璃整体偏深，室内层次不足；林下植物高频密集，群落变化还可加强；廊下材质辨识较弱。远景的平坦地平线削弱场所感。这些是截图观察，不能据此断定动态闪烁或当前帧率。

**设计与细节分配**

继续“浅矿物墙面、克制金属幕墙、木檐、两庭院”的现代园区，强化入口、林下、廊下三种空间性格。建设优先级为构造与尺度、光照关系、材质分层、植物结构，最后才是微小装饰。

| 对象 | 真实几何 | 材质与远景表示 |
|---|---|---|
| 建筑 | 轮廓、窗洞、檐口、台阶、近景倒角和深缝 | 毛孔、细木纹、浅划痕交给材质；远层合并细框，保留开口比例 |
| 玻璃 | 近景框、胶条、少量真实室内和可见玻璃边缘 | 远层延续程序室内视差；反射精度按距离和重要性分配 |
| 植物 | 近景根颈、分枝接头、弯曲叶片 | 中景枝叶簇，远景由同一生成树烘焙多视图表示；保持树冠轮廓与明暗 |
| 地面 | 路缘、排水缝、接触点、近景草叶 | 微粒、远处短草、轻微污染用可过滤的程序纹理 |

程序材质需同时描述大尺度批次差异、中尺度加工方向和微尺度粗糙度；污迹由接缝、雨水路径与遮蔽产生，避免全表面统一随机噪声。细节低于像素尺度就过滤，不靠锐化保留。PBRT 的采样分析直接支持这种频率限制。[PBRT：纹理采样与抗锯齿](https://pbr-book.org/4ed/Textures_and_Materials/Texture_Sampling_and_Antialiasing)

**光照与 WebGPU 的视觉收益**

先以固定晴日建立太阳、程序天空、环境反射和间接光的共同基准。现有 [rendering.js](../../src/campus/rendering.js) 已避免环境重复计算太阳，[indirect-light.js](../../src/campus/indirect-light.js) 已用粗网格记录天空可见度与一次漫反射，应继承此职责划分。廊下需检查天空遮蔽与地面反弹，不能只抬曝光。SSGI 可补局部变化；它读取屏幕颜色、深度、法线，因此无法单独提供完整的屏外信息，这是依据输入作出的限制判断。保留世界空间间接光基底，并校准叠加权重，避免重复增亮。[Three.js SSGINode](https://threejs.org/docs/pages/SSGINode.html)

玻璃必须同时协调角度相关的反射、透射、室内亮度和遮阳构件；近景平面反射与远景探针可分工。不能把所有玻璃调成镜子，也不应全园区无差别开启昂贵透射。Fresnel 反射/透射关系有物理依据，Three.js 也明确复杂物理材质增加逐像素成本。[PBRT：介质 BSDF](https://pbr-book.org/4ed/Reflection_Models/Dielectric_BSDF)、[Three.js 物理材质](https://threejs.org/docs/pages/MeshPhysicalMaterial.html)

WebGPU 专属投入优先用于按屏幕误差选择植物表示、并行更新风场、复用生成结果，把预算给可见近景。它们是候选优化，须测量后决定，不能承诺自动提升写实。植物色差应随个体、枝系与叶龄相关，保持根部固定和分枝约束；叶片薄透光不能变成自发光。

时间稳定性是独立质量项。SSGI/SSR 降噪与全画面抗锯齿分别验证：官方 `TemporalReprojectNode` 不做相机亚像素抖动，不能代替 TAA；本机 Three.js 0.186.1 另有 `TRAANode`。风动须提供前后帧形变信息，切镜、太阳变化和分辨率变化须使相应历史失效。[Three.js TemporalReprojectNode](https://threejs.org/docs/pages/TemporalReprojectNode.html)

动态分阶段：先固定太阳与无风建立基准；再加入可复现微风，同步主画面、阴影和反射；随后做多个时间预设。连续太阳移动放到缓存失效、间接光更新与反射更新全部成立后，不能让夕阳配正午缓存。首版不承诺全昼夜或风力学求解。

**第一完整场景及最终验收**

第一场景为一座完整庭院、两栋相对建筑及连续玻璃柱廊，包含铺地、主乔木、灌木、草坪和可见背景，先跑通全部表现链路；它是验证阶段，不替代最终园区。

建立固定种子、太阳、曝光、1080p 和同位置相机基准；保留现有 [tour.js](../../src/campus/tour.js) 的约 1.7 米人眼高度，新增距玻璃约 1 米、距树干约 0.8 米、距地面约 0.5 米的细节镜头。分别检查正视/掠射玻璃、逆光叶片、晴地到廊下、树根接地与屋顶远望。记录静帧、暂停累积结果及每段至少 10 秒运动，不能用静态累积图代表实时效果。

最终恢复七栋、两庭院、完整环路、屋顶和外围环境；六类漫游镜头与自由探索均需通过。判据为正常速度无明显跳变/拖影，近景无穿帮和悬浮，转动时反射有合理视差，阴影里仍可区分木/石/金属，退远后树冠不突然消失。与当前相同镜头并排审查，同时对照真实照片中的构造与明暗关系；画质收益与帧耗时分别报告。

**最先验证的五个视觉风险**

1. 玻璃：探针、平面反射、透射和室内切换产生接缝或漂移；沿幕墙横移测试。
2. 植物：LOD 改变树冠体积、颜色或阴影；连续进退并看逆光轮廓。
3. 时间累积：风动叶片、细框和切镜出现拖影；逐帧检查并与关闭累积对照。
4. 间接光：廊下漏光、过黑，或 SSGI 随取景改变整体亮度；平移镜头并分别关闭贡献项。
5. 材质尺度：程序重复、噪点闪烁、远景过锐；相同表面从 0.5 米拉远到全景，检查过滤与粗糙度变化。

**第二轮交叉评审：对架构方案的条件裁决**

已阅读 [architecture.md](architecture.md)。固定日光、世界空间探针、有限平面反射和 TRAA 可以作为完整七栋园区的最小表现主线；但它们的名称并不证明写实成立。固定日光不是范围缩水，因为目标没有要求昼夜循环；限制反射预算也合理。真正需要补充的是以下三项约束。

1. **探针按空间边界布置，不能只按均匀间距铺满。** 柱廊、薄墙内外、屋顶挑檐与树冠下要分别验证遮蔽。若探针分区和插值仍无法防止漏光，应给问题表面加入程序生成的静态可见性/辐照数据；SSGI 不能成为掩盖世界空间错误的必要条件。基础光照在关闭 SSGI 后仍须成立。
2. **“关键玻璃”由当前视角决定，不能只绑定六个预设镜头。** 自由探索可能靠近任意幕墙。近景、低粗糙度、大屏幕面积的立面优先分配平面反射；角部同时可见两面时测试资源切换，不能让当前未选立面突然回到明显错误的探针视差。若预算无法支持，须改善探针视差校正、调整更新率或重新分配精度；不能偷偷禁用这段自由探索。漫游中反射对象移出主画面后仍应存在。
3. **TRAA 是候选质量方案，需赢过空间抗锯齿基线。** 细框、逆光叶片与玻璃高光各自测试。若它通过模糊消除闪烁，或为保细节引入拖影，不能只凭静图更干净就接受。需提供正确形变运动向量与历史失效；TRAA 路线关闭 MSAA，空间基线另行测试，不把两者和 SSR、SSGI 一起堆叠。官方区分了整幅画面的 TRAA 与局部效果的重投影。[Three.js TRAA](https://threejs.org/docs/pages/TRAANode.html)、[TemporalReprojectNode](https://threejs.org/docs/pages/TemporalReprojectNode.html)

最小必要链路是：程序天空＋固定太阳，稳定且能覆盖自由视角的直接阴影，带空间边界的间接光，尺度可信的 PBR 材质与薄叶透光，玻璃反射/室内层次，合理 LOD，以及经过运动对照的抗锯齿。接触阴影优先由几何和直接阴影成立；局部 AO 只补缺口。SSR、SSGI、强景深、运动模糊、体积云、实时多反弹、连续太阳和复杂风力学均可延期。简单微风也应在静态基准通过后加入；GPU 裁剪优化不可改变投影与反射中的场景。

**统一对比与明确判退条件**

以下距离与阈值是拟定验收标准，不是已经通过的结果。新旧版本采用相同随机种子、相机位置/朝向/FOV、输出尺寸 1920×1080、太阳方向、材质基色基准、色调映射与白平衡；关闭自动曝光。先在固定中性灰检查片上校准太阳/天空的强度映射，记录两套曝光数值后锁定，禁止逐镜头提亮新版。不能仅靠相同曝光数字假定不同光照实现已匹配。

| 检查 | 拟定观察尺度 | 足以判退的反例 |
|---|---|---|
| 幕墙与柱廊 | 眼高 1.7 米，距玻璃 1 米，平移至少 3 米；正视与约 75° 掠视 | 树或对楼随相机粘在玻璃上；对象出主画面即消失；相邻反射分区有可见接缝；玻璃呈统一黑板 |
| 阴影与间接光 | 穿过晴地/檐下边界，距柱和墙各约 0.5–1 米 | 封闭薄墙透入大块日光；平移取景导致同一哑光表面明显跳亮；柱脚/树根呈悬浮阴影 |
| 树木与地面 | 树干 0.8 米、灌木 0.5 米；随后退到 10/30/80 米 | 可见断枝、根部滑动；LOD 使冠幅或透光突然变化；草坪退远后整片变色/消失 |
| 时间稳定性 | 每镜头不少于 10 秒，步行约 1 米/秒；含缓慢转头、骤停和切镜 | 正常速度可辨窗框双影、叶片拖尾、地缝爬动；切镜后仍可辨认上一镜头内容 |
| 全园区覆盖 | 原六种镜头、七栋可达立面、两庭院、屋顶俯视和外围边界 | 只有演示柱廊可信，换楼即穿帮；背景露出场景边缘；降低画质后阴影/反射缺失整株树 |

每组保存原版与新版的实时连续帧、刚停止帧和明确标注累计时长的静止图，另留无时域基线。先人工判定上述可见错误，再报告局部亮度、边缘残影等指标；任何单一相似度分数都不能替代这些判退条件。性能比较也应使用这套固定构图与曝光，不用简化画面后的帧率宣称 WebGPU 获胜。
